# 트러블슈팅 기록

> 문제 → 원인 → 해결 → 다시 안 생기게 한 것 순서로 적어요. 발표·면접에서 "어려웠던 점"의 근거가 돼요.

## TS-01. 예약 시각이 9시간 당겨져 모델에 전달됨 (11/2)

- **증상:** core가 `"startAt": "2026-11-03T14:00:00+09:00"`을 줬는데 `my_reservations` 도구 결과에는 `"2026-11-03T05:00:00Z"`가 나왔어요. 모델은 이걸 보고 "오전 5시 예약"이라고 답할 수 있어요.
- **원인:** Jackson은 `OffsetDateTime`을 읽을 때 기본으로 UTC로 바꿔 둬요(`ADJUST_DATES_TO_CONTEXT_TIME_ZONE`). 같은 순간이라 값은 맞지만, 모델은 시차를 계산하지 않고 숫자를 그대로 읽어요.
- **해결:** core 응답을 도구 결과로 바꿀 때 `atZoneSameInstant(Asia/Seoul)`로 서울 시간에 되돌려요 (`CoreReservationClient.seoul`).
- **재발 방지:** 테스트 `MyReservationsToolTest.returnsMyReservations`가 결과에 `+09:00` 문자열이 있는지 확인해요. 이 테스트가 처음 실패하면서 문제를 찾았어요.
- **배운 점:** 사람이 읽는 API와 달리 모델이 읽는 값은 "같은 순간"이면 충분하지 않아요. 표시 형식까지 맞춰야 해요.
