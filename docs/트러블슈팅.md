# 트러블슈팅 기록

> 문제 → 원인 → 해결 → 다시 안 생기게 한 것 순서로 적어요. 발표·면접에서 "어려웠던 점"의 근거가 돼요.

## TS-01. 예약 시각이 9시간 당겨져 모델에 전달됨 (11/2)

- **증상:** core가 `"startAt": "2026-11-03T14:00:00+09:00"`을 줬는데 `my_reservations` 도구 결과에는 `"2026-11-03T05:00:00Z"`가 나왔어요. 모델은 이걸 보고 "오전 5시 예약"이라고 답할 수 있어요.
- **원인:** Jackson은 `OffsetDateTime`을 읽을 때 기본으로 UTC로 바꿔 둬요(`ADJUST_DATES_TO_CONTEXT_TIME_ZONE`). 같은 순간이라 값은 맞지만, 모델은 시차를 계산하지 않고 숫자를 그대로 읽어요.
- **해결:** core 응답을 도구 결과로 바꿀 때 `atZoneSameInstant(Asia/Seoul)`로 서울 시간에 되돌려요 (`SeoulTime.of`, 처음엔 `CoreReservationClient.seoul`).
- **재발 방지:** 테스트 `MyReservationsToolTest.returnsMyReservations`가 결과에 `+09:00` 문자열이 있는지 확인해요. 이 테스트가 처음 실패하면서 문제를 찾았어요.
- **배운 점:** 사람이 읽는 API와 달리 모델이 읽는 값은 "같은 순간"이면 충분하지 않아요. 표시 형식까지 맞춰야 해요.

## TS-02. 로컬은 통과, CI만 `ReservationQueryPort` 빈 없음 (11/2)

- **증상:** 로컬 `mvn verify`는 통과하는데 GitHub Actions에서 `No qualifying bean of type 'ReservationQueryPort'`로 테스트 7개가 모두 실패했어요.
- **원인:** `.gitignore`의 `out/`(IntelliJ 출력 폴더)이 **모든 깊이의** `out` 폴더를 무시해요. 그래서 팀 컨벤션 패키지 `adapter/out/core/CoreReservationClient.java`가 커밋에서 빠졌어요. 로컬에는 파일이 있어서 몰랐어요.
- **해결:** `/out/`처럼 앞에 `/`를 붙여 루트 폴더만 무시해요. 빠진 파일을 커밋했어요.
- **재발 방지:** PR 전에 `git status --ignored`로 무시된 소스가 없는지 봐요. 새로 clone한 폴더에서 `mvn verify`를 한 번 돌려요. core는 이미 `/out/`이라 괜찮아요(확인함).

## TS-03. 테스트 클래스를 하나 더 만들자 예전 테스트가 깨짐 (11/2)

- **증상:** `find_available_rooms` 테스트를 추가하고 공통부(`McpToolTestSupport`)로 묶자, 혼자 돌리면 통과하던 `MyReservationsToolTest` 3개가 함께 돌릴 때만 실패했어요. 가짜 코어에 넣은 응답이 도구에 도착하지 않았어요.
- **원인:** Spring 테스트는 설정이 같으면 문맥(ApplicationContext)을 캐시해 여러 클래스가 같이 써요. 그런데 WireMock 확장(`@RegisterExtension`)은 클래스마다 새 포트로 다시 떴어요. 캐시된 문맥은 첫 클래스 때의 포트를 계속 불렀어요.
- **해결:** 가짜 코어를 JVM에 하나만 띄우고(`static` 초기화), 테스트가 끝날 때마다 `resetAll()`로 응답만 지워요. 주소가 바뀌지 않아요.
- **재발 방지:** 도구 통합 테스트는 모두 `McpToolTestSupport`를 상속해요. 문맥을 매번 새로 띄우는 `@DirtiesContext`는 쓰지 않았어요. 테스트가 클래스 수만큼 느려지기 때문이에요.
- **배운 점:** 테스트 하나하나가 아니라 "테스트끼리 무엇을 공유하는가"를 봐야 해요. 공유되는 것(문맥)과 매번 바뀌는 것(포트)이 섞이면 실행 순서에 따라 깨져요.

## TS-04. 가짜 Gemini에 POST하면 `RST_STREAM`으로 끊김 (11/2)

- **증상:** `GeminiLlmClientTest`가 모두 "AI 비서가 지금 응답하지 않아요"로 실패했어요. 원인 예외는 `IOException: Received RST_STREAM: Stream cancelled`였어요.
- **원인:** JDK `HttpClient`는 기본이 HTTP/2라서, `http://` 주소에는 HTTP/1.1로 보내면서 h2c 업그레이드를 같이 요청해요. 가짜 서버(WireMock)는 본문이 있는 POST의 업그레이드를 받다가 스트림을 끊었어요. mcp-server의 core 호출은 같은 방식인데 통과해서 처음엔 원인을 못 찾았어요(확인 필요: 본문 크기나 서버 설정 차이로 추정).
- **해결:** 모델 어댑터의 `HttpClient`를 `HTTP_1_1`로 고정했어요. 진짜 Gemini는 `https`라 영향이 없어요.
- **재발 방지:** 로컬 Ollama(`http://`)도 같은 문제가 날 수 있어서 #14 어댑터도 HTTP/1.1로 만들어요(추정, 확인 필요).
