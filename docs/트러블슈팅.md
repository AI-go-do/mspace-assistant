# 트러블슈팅 기록

> 문제 → 원인 → 해결 → 다시 안 생기게 한 것 순서로 적어요. 발표·면접에서 "어려웠던 점"의 근거가 돼요.

## TS-01. 예약 시각이 9시간 당겨져 모델에 전달됨 (11/2)

- **증상:** core가 `"startAt": "2026-11-03T14:00:00+09:00"`을 줬는데 `my_reservations` 도구 결과에는 `"2026-11-03T05:00:00Z"`가 나왔어요. 모델은 이걸 보고 "오전 5시 예약"이라고 답할 수 있어요.
- **원인:** Jackson은 `OffsetDateTime`을 읽을 때 기본으로 UTC로 바꿔 둬요(`ADJUST_DATES_TO_CONTEXT_TIME_ZONE`). 같은 순간이라 값은 맞지만, 모델은 시차를 계산하지 않고 숫자를 그대로 읽어요.
- **해결:** core 응답을 도구 결과로 바꿀 때 `atZoneSameInstant(Asia/Seoul)`로 서울 시간에 되돌려요 (`SeoulTime.of`, 처음엔 `CoreReservationClient.seoul`).
- **재발 방지:** 테스트 `MyReservationsToolTest.returnsMyReservations`가 결과에 `+09:00` 문자열이 있는지 확인해요. 이 테스트가 처음 실패하면서 문제를 찾았어요.
- **배운 점:** 사람이 읽는 API와 달리 모델이 읽는 값은 "같은 순간"이면 충분하지 않아요. 표시 형식까지 맞춰야 해요.

## TS-02. 로컬은 통과, CI만 `ReservationQueryPort` 빈 없음 (11/2)

- **증상:** 로컬 `mvn verify`는 통과하는데 GitHub Actions에서 `No qualifying bean of type 'ReservationQueryPort'`로 테스트 7개가 모두 실패했어요.
- **원인:** `.gitignore`의 `out/`(IntelliJ 출력 폴더)이 **모든 깊이의** `out` 폴더를 무시해요. 그래서 팀 컨벤션 패키지 `adapter/out/core/CoreReservationClient.java`가 커밋에서 빠졌어요. 로컬에는 파일이 있어서 몰랐어요.
- **해결:** `/out/`처럼 앞에 `/`를 붙여 루트 폴더만 무시해요. 빠진 파일을 커밋했어요.
- **재발 방지:** PR 전에 `git status --ignored`로 무시된 소스가 없는지 봐요. 새로 clone한 폴더에서 `mvn verify`를 한 번 돌려요. core는 이미 `/out/`이라 괜찮아요(확인함).

## TS-03. 테스트 클래스를 하나 더 만들자 예전 테스트가 깨짐 (11/2)

- **증상:** `find_available_rooms` 테스트를 추가하고 공통부(`McpToolTestSupport`)로 묶자, 혼자 돌리면 통과하던 `MyReservationsToolTest` 3개가 함께 돌릴 때만 실패했어요. 가짜 코어에 넣은 응답이 도구에 도착하지 않았어요.
- **원인:** Spring 테스트는 설정이 같으면 문맥(ApplicationContext)을 캐시해 여러 클래스가 같이 써요. 그런데 WireMock 확장(`@RegisterExtension`)은 클래스마다 새 포트로 다시 떴어요. 캐시된 문맥은 첫 클래스 때의 포트를 계속 불렀어요.
- **해결:** 가짜 코어를 JVM에 하나만 띄우고(`static` 초기화), 테스트가 끝날 때마다 `resetAll()`로 응답만 지워요. 주소가 바뀌지 않아요.
- **재발 방지:** 도구 통합 테스트는 모두 `McpToolTestSupport`를 상속해요. 문맥을 매번 새로 띄우는 `@DirtiesContext`는 쓰지 않았어요. 테스트가 클래스 수만큼 느려지기 때문이에요.
- **배운 점:** 테스트 하나하나가 아니라 "테스트끼리 무엇을 공유하는가"를 봐야 해요. 공유되는 것(문맥)과 매번 바뀌는 것(포트)이 섞이면 실행 순서에 따라 깨져요.

## TS-04. 실제 core와 붙이자 오프셋 없는 시각이 거절됨 (11/3)

- **증상:** 머지된 core를 로컬 PostgreSQL로 띄워 MCP 서버와 붙여 보니, `create_reservation`에 `2026-11-04T14:00`처럼 오프셋 없이 넣으면 "시각을 모두 넣어야 해요"로 거절됐어요. 가짜 core 테스트는 모두 `+09:00`이 붙은 값만 써서 몰랐어요.
- **원인:** 도구가 `OffsetDateTime.parse`만 썼어요. 모델은 사람 말("내일 2시")을 바꿀 때 오프셋을 빼는 일이 많아요(확인 필요: #9 측정에서 횟수를 잴 예정). 거절되면 모델이 같은 호출을 되풀이하다 반복 최대 횟수(8번)에 닿을 수 있어요.
- **해결:** 오프셋이 없으면 서울 시간으로 봐요(`LocalDateTime` → `Asia/Seoul`). 오프셋이 있으면 그대로 써요. 날짜 형식 자체가 틀리면 전과 같이 400이에요.
- **재발 방지:** 시각 입력 테스트에 오프셋 없는 값을 넣었어요. 도구 설명의 예시는 계속 `+09:00`을 붙여 모델이 기본 형식을 따르게 둬요.
- **함께 확인한 것 (실제 core 기준, 11/3):** 경로 7개와 응답 모양(`/me`의 `room`·`owner`·`accessCode`, 생성 응답 7개 필드, 상태 변경 `{id,status}`)이 비서 DTO와 같아요. 시각은 `+09:00`(존 이름 없음)으로 와요. 오류 코드 `RESERVATION_TIME_TAKEN`·`OWNER_HAS_ACTIVE_RESERVATION`·`PARTICIPANT_TIME_TAKEN`·`PARTICIPANT_NOT_FOUND`·`NOT_RESERVATION_OWNER`·`RESERVATION_NOT_FOUND`·`RESERVATION_NOT_CANCELABLE`가 그대로 전달돼요. 같은 멱등 키 두 번은 201 → 200이고 예약은 1건이에요.
- **배운 점:** 가짜 서버 테스트는 "내가 상상한 입력"만 확인해요. 모델이 실제로 보낼 입력과 실제 서버의 응답은 한 번은 진짜로 붙여 봐야 보여요.

## TS-05. 가짜 Gemini에 POST하면 `RST_STREAM`으로 끊김 (11/2)

- **증상:** `GeminiLlmClientTest`가 모두 "AI 비서가 지금 응답하지 않아요"로 실패했어요. 원인 예외는 `IOException: Received RST_STREAM: Stream cancelled`였어요.
- **원인:** JDK `HttpClient`는 기본이 HTTP/2라서, `http://` 주소에는 HTTP/1.1로 보내면서 h2c 업그레이드를 같이 요청해요. 가짜 서버(WireMock)는 본문이 있는 POST의 업그레이드를 받다가 스트림을 끊었어요. mcp-server의 core 호출은 같은 방식인데 통과해서 처음엔 원인을 못 찾았어요(확인 필요: 본문 크기나 서버 설정 차이로 추정).
- **해결:** 모델 어댑터의 `HttpClient`를 `HTTP_1_1`로 고정했어요. 진짜 Gemini는 `https`라 영향이 없어요.
- **재발 방지:** 로컬 Ollama(`http://`)도 같은 문제가 날 수 있어서 Ollama 어댑터(#14)도 HTTP/1.1로 고정했어요. 진짜 Ollama에서도 같은 문제가 나는지는 확인 필요예요.

## TS-06. 에이전트 모듈에서 MCP 클라이언트 버전이 안 잡힘 (11/2)

- **증상:** `agent/pom.xml`에 `io.modelcontextprotocol.sdk:mcp`를 버전 없이 넣자 `dependencies.dependency.version is missing`으로 빌드가 멈췄어요.
- **원인:** mcp-server는 Spring AI 스타터가 SDK를 끌어와서 버전을 몰라도 됐어요. `spring-ai-bom` 2.0.2는 SDK 버전을 관리하지 않아요(확인함: bom에 항목 없음).
- **해결:** 루트 `pom.xml`의 `dependencyManagement`에 `mcp-sdk.version` 2.1.0을 두고 두 모듈이 같은 버전을 쓰게 했어요. 새 라이브러리가 아니라 mcp-server가 이미 쓰던 것이에요.
- **재발 방지:** Spring AI를 올릴 때 스타터가 끌어오는 SDK 버전과 루트 값을 같이 맞춰요.

## TS-07. 개인정보 가리기는 규칙이라 표기가 바뀌면 샌다 (11/2)

- **증상:** 리뷰에서 가리지 못하는 전화번호 표기가 차례로 나왔어요. 일반 전화 `062-230-1234`, `+82 62-…`, `+82-(0)62-…` 같은 것들이에요.
- **원인:** `PrivacyMask`는 정규식이라 정해 둔 모양만 잡아요. 이름은 규칙으로 가릴 방법이 없어서 처음부터 빠져 있어요.
- **해결:** 휴대폰·일반 전화·`+82`·`(0)` 표기를 패턴에 넣었고, 표기마다 `AgentLoopTest.masksPersonalInfo`에 회귀 테스트를 추가했어요.
- **한계(11/2 결정):** 이름과 새로운 표기는 남을 수 있어요. 그래서 시연은 가짜 데이터로만 하고, 참여자 학번은 대화가 아니라 확인 카드에서 받아요(A-5). 학교 도입 때는 데이터가 학교 밖으로 나가지 않는 Ollama를 다시 검토해요.

## TS-08. 기본 모델 `gemini-2.5-flash`를 새 키로 못 쓸 수 있음 (11/5)
- **증상:** 시연용 Gemini 키를 새로 만들 차례에 기본값 `gemini-2.5-flash`가 그대로 쓸 수 있는 모델인지 확실하지 않았어요.
- **원인:** [공식 deprecations 문서](https://ai.google.dev/gemini-api/docs/deprecations)에 2.5 계열은 "예전에 쓰던 사용자만" 쓸 수 있고, 새 프로젝트에는 더 새 모델을 권한다고 적혀 있어요.
- **해결:** 기본값을 `gemini-3.5-flash-lite`로 바꿨어요. 도구를 잘못 고르면 `GEMINI_MODEL=gemini-3.8-flash`로 바꿔요. Gemini 3 계열은 도구 호출 때 `thoughtSignature`를 되돌려 보내야 하는데(안 보내면 400), `GeminiLlmClient`가 이미 그렇게 해요.
- **남은 확인:** 무료 한도 숫자는 [공식 문서](https://ai.google.dev/gemini-api/docs/rate-limits)에 표가 없고 AI Studio에서 프로젝트별로만 보여요. 하루 한도는 태평양 시간 자정(한국 17:00)에 초기화돼요. 무료 등급 입력은 Google이 제품 개선에 쓸 수 있어서([가격 문서](https://ai.google.dev/gemini-api/docs/pricing)) 가짜 데이터만 보내는 규칙을 그대로 지켜요.
