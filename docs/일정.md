## 다른 레포에 기대는 것
- **예약 코어 v2 (지영):** 쓰기 도구는 코어 v2 API가 나와야 실제로 붙어요. 그전에는 v1 API 명세 기준의 가짜 서버(WireMock)로 개발하고 테스트해요
- **멱등 키:** 같은 확인을 두 번 보내도 예약이 두 번 생기지 않게 하려면 코어가 멱등 키를 받아야 해요. M2 안에 지영님과 합의해요
- **배포 (재웅):** 인프라 레포 규칙이 정해지면 Docker 이미지·CI를 맞춰요

## M1. 설계와 뼈대 (10/31 ~ 11/6)
목표: MCP 서버가 뜨고 읽기 도구 하나가 가짜 코어를 불러 응답한다.
- [ ] 도구 명세: 도구마다 부르는 API, 요청·응답 정리 (`docs/도구-명세.md`)
- [ ] MCP 서버 구현 방식 결정 (A-1: Spring AI MCP의 Spring Boot 4.1 지원 확인)
- [ ] 쓰기 도구 두 단계 확인 흐름 설계 (`docs/설계.md`, 시퀀스 다이어그램)
- [ ] `mcp-server`, `agent` 모듈 구조와 Gradle 뼈대, CI에서 빌드·테스트
- [ ] 읽기 도구 1개(`room_status`)를 가짜 코어로 연결

## M2. 읽기 도구와 에이전트 반복 (11/7 ~ 11/13)

- [ ] 읽기 도구 전체: `find_available_rooms`, `room_status`, `my_reservations`
