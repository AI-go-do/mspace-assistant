# AI 비서 성능 개선: 지시문 한 줄씩 고치고, 모델은 같은 시험지로 비교하기

> 작성일: 2026-11-11, 프로젝트: mspace-assistant(오디 비서), 스택 버전: Spring Boot 4.1.2 / Java 21 / Spring AI 2.0.2 / DB 없음(대화 맥락은 Redis) / 운영 모델 gemini-3.5-flash-lite
> 근거: PR #105·#106·#108(지시문), #110(젯슨 Ollama), #111·#112(3.8 Flash), #113(채점기), #115(TS-16), `scripts/eval/results/scoreboard.md`

## 0. 먼저 짚을 것: "프롬프트 증강"이라는 이름

- 이번에 한 일은 **시스템 지시문에 규칙을 한 줄씩 더한 것**이에요. 검색 결과를 지시문에 끼워 넣는 RAG(검색 증강 생성)는 하지 않았어요.
- 보통 "프롬프트 증강"이라고 하면 RAG 쪽으로 알아듣는 사람이 많아요(추정). 발표·면접에서는 **"지시문 개선(prompt refinement)"** 또는 **"규칙 추가"**라고 부르는 게 오해가 적어요.

## 1. 결론

- 운영 모델 **3.5 Flash Lite는 그대로 두고 지시문만 v1 → v2 → v3로 두 줄 더해** 89.8점·심각 오류 2.7을 **100점·심각 0**으로 올렸어요(#106·#108).
- 같은 시험지(발화 35개, 가짜 도구, 고정 시각)로 모델만 바꿔 쟀더니 젯슨 3B 모델 둘(31.2·39.7)과 3.8 Flash(응답 없음)는 모두 탈락이에요. **모델을 바꾸는 것보다 지시문을 고치는 게 싸고 효과가 컸어요.**
- 3.8 Flash는 품질 전에 **응답 시간에서 떨어졌어요**. 같은 맥·같은 키로 "안녕"만 보내도 1.4초 대 343초였어요(TS-16).

## 2. 문제 → 해결

### 2-1. 지시문 개선
- **문제:** 기준(v1)에서 같은 심각 오류 세 개가 되풀이됐어요.
  - C19 "쓸 방 있나"처럼 묻기만 했는데 예약 카드를 띄움
  - C11 "연장해 줘"처럼 분이 없는데 묻지 않고 연장 카드를 띄움
  - C12 "지금 바로 1시간"에서 끝 시각을 30분 칸이 아닌 11:25로 넣음
- **원인:** 지시문에 "쓰기 도구는 언제 부르나"와 "즉시 시작 끝 시각은 어떻게 맞추나"가 없었어요. 모델은 빈칸을 그럴듯하게 채워요.
- **해결:** 판마다 한 줄씩만 더했어요.
  - v2: 쓰기 도구는 "하라고 했고 값이 다 정해졌을 때만". 묻기만 하면 방을 보여 주고 되묻기. 분 없는 연장은 몇 분인지 묻기 → C19·C11 사라짐, 99.3
  - v3: 즉시 시작 끝은 다음 정각·30분으로 올리기(예시 시각은 시험 문항과 다르게 14:17·09:40) → C12 고쳐짐, 100·심각 0
- **대안과 기각 이유:** 아래 4장 표.

### 2-2. 채점기 보강(#113)
- **문제:** 채점기가 틀리게 채점한 경우가 세 가지 있었어요.
  - 확인 카드가 나온 뒤 모델 호출이 실패하면 `AgentLoop`가 정해진 글(`CARDS_ONLY_REPLY`)로 답해요. 그런데 채점기는 이걸 정상 답으로 셌어요.
  - C13: "수업이 없어요"(틀린 답)를 걸러 내지 못했어요.
  - C17: 시간표 꼬리말에 들어 있는 "시간표"를 되묻기로 오인했어요.
- **해결:**
  - 카드 뒤 모델 오류도 오류로 셌어요.
  - C13에는 "수업이 없"이 들어간 꼴을 금지어로 넣었어요.
  - C17은 같은 문장 안에 단서 말과 묻는 꼴(물음표, "알려 주세요")이 함께 있어야 되묻기로 보게 했어요.
- **결과:** 지난 판들에 다시 적용하면 v1 −0.9, v2 +0.3, v3는 0으로 바뀌어요(저장된 120자 답 기준 추정). 판단(채택·탈락)은 그대로예요.

### 2-3. 3.8 Flash 탈락(#111·#112, TS-16 #115)
- **증상:**
  - 20초 제한으로 재니 7문항 모두 시간 초과였어요.
  - 60초로 늘려도 4문항은 시간 초과, 2문항은 503, 1문항은 429였어요.
- **원인 확인:** 우리 코드를 빼고 curl로 "안녕"만 보내 비교했어요.
  - 3.5 Flash Lite: 200, 1.4초
  - 3.8 Flash: 200, 343초. 전날에는 1초 만에 503
  - 키·이름·요청 모양은 정상이에요. 구글 무료 등급 대기열이 원인으로 보여요(추정, 구글 내부는 못 봐요).
- **결정:** 탈락이에요. 운영은 호출 하나 20초, 대화 전체 45초까지 기다려요. 한 마디에 6분이면 다시 재도 무료 한도(하루 20회)만 써요.

## 4. 기술별 비교: 무슨 문제 → 대안 → 대안을 썼다면 → 약점

### 4-1. 지시문 개선 vs 모델 교체
- **푸는 문제:** 모델이 규칙을 몰라 생기는 같은 실수(C19·C11·C12)
- **대안 비교**

  | | 지시문 한 줄 추가(채택) | 더 큰·새 모델로 교체 |
  |---|---|---|
  | 비용 | 0원, 한 판 측정 | 3.8 Flash는 무료 20회/일, 유료면 돈(사비 0원 원칙 위반) |
  | 효과 | 89.8 → 100, 심각 2.7 → 0 | 3.8 Flash는 응답이 없어 측정 불가 |
  | 원인 추적 | 한 줄 = 한 원인 | 모델 안이 바뀌어 무엇이 좋아졌는지 모름 |
- **대안을 썼다면:** 3.8 Flash로 바꿨다면 시연 중 답이 안 오고, 하루 20회면 대화 몇 번(한 대화 2~3회 호출)에 끝나요.
- **약점:**
  - 규칙이 늘수록 지시문이 길어져 입력 토큰이 늘고 응답이 느려질 수 있어요(v2 13959 → v3 14050 토큰).
  - 시험지에 맞춘 규칙만 늘리면 시험지 밖 질문에서 틀릴 수 있어요(과적합). 그래서 예시 시각을 시험 문항과 다르게 썼어요.

### 4-2. 로컬 젯슨(Ollama) vs 클라우드(Gemini)
- **푸는 문제:** 학생 대화가 학교 밖으로 나가지 않게 하기(학교 도입 시), 무료 한도에서 벗어나기
- **대안 비교**

  | | 젯슨 보드 A + 3B 모델 | Gemini 3.5 Flash Lite(채택) |
  |---|---|---|
  | 점수 | qwen2.5:3b 31.2 / llama3.2:3b 39.7 | 100 |
  | 심각 오류 | 15.0 / 7.0 | 0 |
  | 평균·최대 시간 | 16.3초·70.8초 / 11.2초·123.1초 | 8.1초·20.7초 |
  | 개인정보 | 학교 안에서 끝남 | 구글로 나감. `PrivacyMask`가 학번(20으로 시작하는 8자리)·전화번호·6자리 숫자 형식만 가리고, **이름은 못 가려요**(학생이 이름을 적으면 그대로 나감) |
  | 비용 | 0원(장비 있음) | 0원(무료 등급) |
- **대안을 썼다면:**
  - 날짜를 지어냈어요(11/6·11/3). 예약 요청에 즉시 시작을 부르고, 도구 호출을 글자로 내보냈어요.
  - [확인]만 누르면 엉뚱한 예약이 생길 수 있었어요.
- **약점(클라우드 쪽):** 구글이 과부하면 우리가 할 수 있는 게 없어요(3.8 Flash가 그 예). 무료 한도도 구글이 정해요.
- **남은 일:** 7B 이상 모델은 젯슨 메모리에 들어가는지부터 확인해야 해요(확인 필요).

### 4-3. 자동 채점기 vs 사람 채점
- **푸는 문제:** 판마다 70대화를 사람이 읽으면 하루에 몇 판 못 재요.
- **대안:** 사람이 전부 읽기, 또는 다른 LLM에게 채점시키기(LLM-as-judge)
- **대안을 썼다면:**
  - 사람 채점은 느리고 사람마다 기준이 달라요.
  - LLM 채점은 채점하는 모델도 흔들리고, 무료 한도를 두 배로 써요(추정).
- **약점:**
  - 글자 포함 여부로 채점하는 방식은 결국 빈틈이 있어요. 예: "날짜는 확인했습니다만 더 도와드릴까요?"는 통과해요.
  - 보완으로 사람이 눈 가리고 10개를 채점해 채점기와 맞춰 봤어요(10/10 일치).

### 4-4. 기준점 비교(한 판에 한 가지) vs 여러 개 한꺼번에 바꾸기
- **푸는 문제:** 점수가 올랐을 때 무엇 덕분인지 알기
- **대안을 썼다면:** v2·v3 규칙을 한꺼번에 넣었으면 C06(금요일 → 11/3) 같은 흔들림까지 규칙 덕으로 착각했을 거예요. v3 단락에도 "이 줄과 상관없는 흔들림이라 v3 덕이라 보지 않음"으로 적었어요.
- **약점:** 판 수가 늘어 무료 한도를 더 써요. v3 2회차는 한도 초과로 다른 프로젝트 키로 다시 쟀어요.

## 5. 실무 Use Case

- **쇼핑몰 상담 봇:** "환불돼요?"라고 물었는데 바로 환불을 실행해 버리는 실수. v2의 "하라고 했고 값이 다 정해졌을 때만 쓰기 도구" 규칙과 같은 꼴이에요. 쓰기 작업은 확인 카드 + 멱등 키로 막아요.
- **사내 일정 비서:** "30분 늘려 줘" 없이 "늘려 줘"만 왔을 때 마음대로 1시간 연장하는 실수. 값이 빠지면 되묻게 해요(C11).
- **모델 공급사 바꾸기 전 회귀 시험:** 새 모델이 나오면 같은 시험지로 점수·심각 오류·시간·한도를 한 표에 놓고 고르면, "최신이라 좋겠지"라는 감 대신 숫자로 정할 수 있어요(3.8 Flash가 그 예).

## 6. 코드

**지시문 v1 → v2 (한 줄 추가)** `scripts/eval/prompts/v2.txt`
```
- 쓰기 도구(create·start_now·cancel·checkout·continue)는 학생이 "잡아 줘·예약해 줘·취소해 줘·연장해 줘"처럼 하라고 했고
  필요한 값이 다 정해졌을 때만 부른다(...). "~있어?", "~있나"처럼 묻기만 하면 찾은 방을 보여 주고 "이대로 잡아 드릴까요?"라고 묻는다.
  "연장해 줘"처럼 몇 분인지 없으면 continue_reservation을 부르지 말고 "몇 분 늘릴까요? (30분 단위, 최대 2시간)"라고 묻는다.
```

**v2 → v3 (한 줄 추가)** `scripts/eval/prompts/v3.txt`


**심각 오류: 실제로 부른 쓰기 도구만 본다** `Scorer.severe`

**#113 카드 뒤 모델 실패도 오류로** `EvalRunner.java`
```java
List<RecordingLlm.Call> calls = llm.drain();
if (error == null) {
    // 카드가 나온 뒤 모델 호출이 실패하면 AgentLoop는 CARDS_ONLY_REPLY로 답한다 → 모델 오류로 센다
```

**429 / 5xx / 그 밖(401·403·404)을 가르는 곳** `GeminiLlmClient.java`
```java
int status = res.getStatusCode().value();
if (status == 429) throw new LlmException("LLM_RATE_LIMITED", "지금 질문이 많아요. ...");   // 한도: 다시 보내도 같음
throw status >= 500 ? new Transient() : unavailable();   // 5xx만 1초 쉬고 한 번 더, 키·이름 오류는 바로 끝
```

- bash: `unset GEMINI_API_KEY; read -rsp "Gemini 키: " GEMINI_API_KEY; echo`
- `export` 안 함: 하면 curl이 환경 변수로 물려받아 같은 계정 프로그램이 볼 수 있어요. `printf`는 셸 내장이라 프로세스 인자에 안 남아요. 평가 실행(`./mvnw`)만 키를 환경 변수로 읽으니 그때만 export해요.

## 7. 엣지 케이스 체크

| 항목 | 이번 작업에서의 상태 | 대응 |
|---|---|---|
| 트랜잭션 롤백 | 해당 없음: 비서는 DB가 없고 쓰기는 core가 해요. 대신 "카드 발급 뒤 모델 실패"가 비슷한 반쪽 상태예요 | 카드는 살려 화면에 주고(`CARDS_ONLY_REPLY`), 실제 예약은 [확인] 때 core가 한 트랜잭션으로. 평가에선 이걸 모델 오류로 셈(#113) |
| 동시성(Race Condition) | 같은 [확인]을 두 번 누르는 경우, 채팅과 확인 결과 저장이 겹치는 경우 | 확인 토큰 = `Idempotency-Key`로 core가 같은 예약을 200으로 돌려줌. 확인 결과는 미룬 글(Redis RPUSH)로 따로 쌓음(TS-12) |
| 인덱스 영향 | 해당 없음: 비서 쪽 DB 조회 없음. 대화 맥락은 Redis 키(`agent:…:<sub>`) 하나로 바로 찾음 | core의 `no_room_overlap` 등 제약은 core 소관 |
| 트래픽 증가 시 병목 | **모델 한도와 대기열이 먼저 막혀요.** 아래 계산 | 아래 7-1 |

### 7-1. 시험 기간에 몰리면
- **한도:** 3.5 Flash Lite 무료는 분당 15회, 하루 500회예요(11/5 AI Studio 실측). 대화 하나에 평균 2.4회 부르니 **분당 약 6대화, 하루 약 210대화**가 끝이에요(점수판 "무료 210대화/일").
- **가정 예:** 학생 100명이 하루 3번씩 쓰면 300대화예요. 하루 한도를 넘어서 오후부터 429("지금 질문이 많아요")가 나와요(가정 계산).
- **서버 대기열:** agent 한 대가 동시에 4건 처리하고 20건까지 줄을 세워요. 줄 끝 요청의 대기는 5바퀴 × 45초 = 225초예요(`application.yml` 주석). 이건 작업 하나가 45초에 끝난다고 가정한 값이고, 아래 9장처럼 작업 하나가 45초를 넘길 수 있어 실제 상한은 더 길어요. 이때 병목은 우리 CPU가 아니라 모델 응답 시간이에요.
- **응답 시간:** 같은 v3도 호출당 2.1초 → 3.4초로 시간대에 따라 흔들렸어요. 붐비는 시간에는 무료 등급 대기열이 길어질 수 있어요(추정).
- **대응 순서**
  1. 브리핑처럼 모델 없이 코드가 바로 답하는 경로를 늘려요(#72·#82, 호출 0회).
  2. 대화당 호출 수를 줄여요. 지시문으로 불필요한 도구 호출을 줄이면 한도가 그만큼 늘어나요.
  3. 서버와 측정을 **다른 구글 프로젝트**로 나눠 측정이 서버 한도를 먹지 않게 해요. 한도는 키가 아니라 프로젝트 단위라, 같은 프로젝트에서 키만 새로 만들면 한도를 같이 써요(지금 측정은 다른 프로젝트 키로 함).
  4. 학교 도입 시에는 로컬 모델이나 유료 등급을 써요. 다만 지금 3B 로컬 모델은 품질 미달이에요.

## 9. 잘못된 전제 / 헷갈린 포인트

- **"직접 불렀는데 1초 만에 실패하면 우리 문제 아님?"** → 1초 503은 상대 서버가 "꽉 찼다"고 바로 돌려보낸 것이에요. 우리 쪽 문제였다면 400·401·403·404가 와요. 다만 이 판단은 같은 키로 다른 모델(1.4초)과 비교하고서야 확정했어요.
- **"비서 시간 제한 60초"(제가 처음에 틀리게 말함)** → 실제로는 Gemini 호출 하나 20초, 대화 전체 45초예요. 60초는 앞단 nginx와 평가 때 늘린 값이에요. 기한은 새 호출 전에만 확인하고 시작한 호출은 끊지 않아요(`AgentLoop.converse`). 게다가 `GeminiLlmClient`는 5xx를 받으면 1초 쉬고 20초짜리 호출을 한 번 더 보내요. 그래서 기한 직전에 시작한 호출이 503 뒤 재시도까지 가면 최악은 약 45 + 20 + 1 + 20 = 86초예요(계산, 실측 아님). 앞단 nginx 60초가 먼저 끊을 수 있지만 결과는 폴링으로 받으니 대화 작업 자체는 계속돼요(추정).
- **"키를 화면에 안 보이게 받았으니 안전"** → `read -rs`는 화면과 셸 기록만 막아요. curl 인자와 `export`한 환경 변수는 같은 계정 프로그램이 볼 수 있어요.
- **"최신 모델이 더 좋겠지"** → 품질 이전에 응답 시간과 무료 한도에서 떨어졌어요.
- **"지시문으로 다 고칠 수 있다"** → 3B 로컬 모델은 같은 v3 지시문을 줘도 날짜를 지어냈어요. 지시문은 모델 능력의 바닥을 올리지 못해요.

## 10. 세미나용 1분 설명

> 저희 AI 비서는 "내일 저녁 7시 셋이서 방 있나?" 같은 말을 예약으로 바꿔요. 처음엔 묻기만 했는데 예약 카드를 띄우는 실수가 있었어요. 그래서 발화 35개짜리 시험지와 자동 채점기를 만들었어요. 맞는 도구 50, 맞는 값 30, 맞는 답 20점이고, [확인]만 누르면 잘못된 예약이 생기는 실수는 "심각 오류"로 따로 셌어요. 기준 지시문 v1은 89.8점, 심각 2.7이었어요. 한 판에 규칙 한 줄만 더해 v2 99.3, v3 100점·심각 0이 됐어요. 같은 시험지로 모델도 바꿔 봤어요. 젯슨의 3B 로컬 모델은 31~40점, 최신 3.8 Flash는 무료 등급 대기열 때문에 "안녕" 한 마디에 343초가 걸려 탈락했어요. 결론은, 모델을 바꾸기 전에 같은 시험지로 재고 지시문부터 고치는 게 싸고 효과가 컸다는 거예요.

<details><summary>Q1. (개념) "심각 오류"는 무엇이고, 일반 감점과 왜 따로 세나요?</summary>

사용자가 [확인]만 눌러도 잘못된 예약·취소·연장이 실제로 일어나는 출력이에요. 예: 틀린 방·시각·예약 번호·분, 부르면 안 되는 쓰기 도구, 확인 전 "완료", 6자리 숫자. 점수 평균은 높아도 이런 실수가 하나 있으면 운영할 수 없어요. 그래서 "심각 0"을 합격 조건으로 따로 둬요. 인원 오류는 core가 막고 카드에도 보여서 심각으로 세지 않아요.
</details>

<details><summary>Q2. (왜) 한 판에 한 가지만 바꾼 이유는?</summary>

점수가 바뀌었을 때 원인을 하나로 좁히려고요. 모델 출력은 회차마다 흔들려요(C06 금요일 → 11/3). 여러 개를 한꺼번에 바꾸면 흔들림까지 규칙 덕으로 착각해요. 기준 행(v1)을 두고 v2·v3, 그다음 v3를 고정한 채 모델만 바꿨어요.
</details>

<details><summary>Q3. (트레이드오프) 젯슨 로컬 모델 대신 Gemini를 고른 대가는?</summary>

얻은 것은 100점·심각 0·평균 8.1초예요. 대가는 세 가지예요. 대화가 구글로 나가고(학번·전화는 정해진 형식만 가리고, 이름은 못 가림), 무료 한도(하루 약 210대화)에 묶이고, 구글 과부하를 우리가 제어하지 못해요. 로컬 3B는 개인정보는 안에 남지만 31~40점·심각 7~15라 쓸 수 없어요.
</details>

<details><summary>Q4. (장애 상황) 시연 중 비서가 "지금 질문이 많아요"만 반복하면?</summary>

- 즉시 대응:
  - 브리핑처럼 모델 없이 도는 기능과 수동 예약 화면으로 넘어가요.
  - 측정 키가 서버와 같은 구글 프로젝트 것인지 확인해요.

- 예방: 측정을 다른 구글 프로젝트로 분리하고 대화당 호출 수를 줄여요.

</details>

## 13. 면접 질문 3개

1. **LLM 기능의 품질을 어떻게 숫자로 관리했나요?**
